# ReliefVue — Colosseum product demo video

**Format:** Separate from the founder pitch. Record your face at the start and end, with the live [ReliefVue website](https://reliefvue.vercel.app/#home) on screen for the demonstration. Submit via YouTube, Loom or Vimeo. Colosseum's limit supplied by Geraldine is **3 minutes**. Aim for **2:45–2:55** after trimming typing and long scrolls. No slide deck or code walkthrough.

The story is **prepare → request → review → trace**. Explain those steps while using the product; there is no need to open the separate **How it works** page.

## Prepare the screen before recording

- Reset the demo and start at [home](https://reliefvue.vercel.app/#home). Use a readable browser zoom, visible pointer and made-up information only.
- The example name is prefilled. For residence type `Fictional Mae Rim, Chiang Mai`; for household type `Room A`. Click **Finish example checks**. The dashboard should then say **You’re ready to follow a response**.
- The dashboard wallet button is a **preview**, not a connected wallet. On payout preference, **Convert to Thai baht** is a planned simulated route. Return to **Keep SOL** before submitting for a simple recording path.
- Trim typing and scrolling, while keeping the clicks and resulting screens in order. Rehearse once against the deployed site because labels may change.

## Accuracy notes for the spoken claims

- The donor receipt, reviewer queue, fund figures and wallet fragments are fictional. The public website shows no confirmed Solana transaction signature. Do not call a sample reference a transaction ID.
- The reviewer case you inspect is **not** the household request submitted earlier; show it as a separate example of the review process.
- One grant per household is the intended rule. The current public walkthrough ends at **Submitted** and does not prove a real payout or production duplicate enforcement.
- Wallet setup, baht conversion, institutional adoption and a four-keyholder treasury are future design directions, not working features of this public demo. A practical starting design would require **3 of 4 independent approvals**, with a recovery and audit process; the exact policy remains to be designed and reviewed.
